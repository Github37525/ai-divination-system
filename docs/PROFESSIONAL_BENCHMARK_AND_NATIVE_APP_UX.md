# 六爻 / 奇门专业基准与原生 App 体验蓝图

> 版本：1.0  
> 日期：2026-08-01  
> 适用范围：iOS、Android、H5/PWA、桌面 Web 及现有确定性规则服务

## 1. 结论先行

当前产品已经具备一组可以用代码、测试和来源记录证明的工程优势，但还不能宣称“术数准确率领先”或“专业能力全面领先”。

- **可以主张**：规则来源可追溯、64 卦与 384 爻结构完整、历法边界明确、排盘与 AI 解读分离、结果可审计、失败可恢复、跨端结果一致。
- **不能主张**：比所有竞品更准、覆盖所有六爻或奇门流派、已经通过大规模真实案例验证、已经得到独立专家共识。
- **六爻现状**：确定性、来源和防错能力较强；起卦方法、神煞广度、专业设置、卦例工作台和复盘效率仍有差距。
- **奇门现状**：对“时家转盘奇门·拆补法”的边界说明清楚；流派数量、格局库、用神和宫位分析深度、独立基准盘数量明显不足。
- **产品机会**：不与传统工具拼“默认把所有术语塞满一屏”，而是做成“新人先看懂、专业者可逐层核验、每个结论能回到规则依据”的双层产品。

## 2. 专业性如何判断

本项目不以商店评分、下载量、文案声量或 AI 文字长度判断专业性。每个模块按以下八项建立证据：

| 维度 | 判断问题 | 当前证据 |
| --- | --- | --- |
| 可重复性 | 同一输入和规则版本能否得到同一盘 | 确定性引擎、版本化规则和自动化测试 |
| 流派边界 | 是否说明采用哪套规则及争议约定 | 六爻规则说明；奇门固定拆补转盘法 |
| 规则覆盖 | 已实现哪些关系、状态、格局和起法 | 完成矩阵与测试清单 |
| 外部锚点 | 是否与经典文本、独立实现或公开盘例核验 | `data/SOURCES.md`、`docs/QIMEN_RULES.md` |
| 解释可追溯 | 白话结论能否定位到盘面事实 | 确定性盘先返回；AI 不得修改排盘 |
| 防错能力 | 矛盾状态、边界时间和失败是否被捕获 | Guardrails、立春边界、失败原记录重试 |
| 复盘能力 | 用户能否记录现实结果并回看判断 | 历史、四状态反馈、会话与审计记录 |
| 专业可配置 | 是否满足不同门派、习惯和高级研究 | 六爻有限；奇门目前只支持固定约定 |

专业验收采用“证据等级”，不使用模糊的“准确率”：

- **A 级**：规则说明、自动化测试、独立锚点和版本记录齐全。
- **B 级**：实现和测试齐全，但独立锚点不足。
- **C 级**：有实现，只有内部样例或描述性说明。
- **实验级**：探索功能，默认不对外作为专业能力宣传。

## 3. 当前能力盘点

### 3.1 已核验的六爻优势

1. 64 个唯一卦码、文王序 1–64、384 条标准爻辞、乾坤用九/用六和数据库 SHA 均有自动核验。
2. 八宫、世应、纳甲、五行、六亲由固定规则生成，并与多个独立实现及公开资料做锚点核验。
3. 本卦、变卦、互卦、综卦、错卦由确定性算法推导；64 卦全量测试覆盖。
4. 已覆盖飞伏神、旬空、月破、日冲、暗动、冲空则实、空破并见、多动爻焦点和乾坤六爻皆动等状态。
5. 真太阳时不只使用经度差，还纳入均时差；立春按实际交接时刻修正年柱与月柱，晚子时换日约定被显式保存。
6. DeepSeek 只解释已经锁定的盘面；模型失败时盘面仍可查看，并可在同一记录上重试。

### 3.2 已核验的奇门优势

1. 明确固定为“时家转盘奇门·拆补法”，不把不同流派规则混成所谓唯一答案。
2. 阴阳遁、局数、三奇六仪、旬首、值符值使、九星八门八神和中宫寄宫均为机械排布。
3. 已用公开参考盘核验值符、值使和关键宫位，并测试九宫结构完整性。
4. 问事结果已有“一眼结论、行动、风险、依据”白话层；终身盘明确起运方向、起运年龄和流年选择。
5. 计算层不直接植入模糊吉凶断语，解释层与排盘层分离。

对标结论：

- **专业深度标杆**：天时六爻、论藏甲-奇门、大师奇门。

- **现代叙事与交互标杆**：爻知、南易六爻。
- **本项目应占据的位置**：不是“术数超市”，而是“可验证的传统决策与复盘工具”。

## 5. UI 必须把专业性变成看得见的证据

### 5.1 起卦前：规则说明卡

默认展示三行，不把用户淹没在术语里：

- 本次方法：`京房纳甲六爻` 或 `时家转盘奇门 · 拆补法`。
- 时间规则：`真太阳时已校正 · 晚子时 23:00 换日`。
- 可信承诺：`AI 不参与排盘，只解释锁定结果`。

点击“查看专业依据”后再显示规则版本、来源、数据库指纹、经纬度和争议约定。

### 5.2 起卦中：六节点真实进度

不能只显示“1/6”。使用六个从下到上的爻位节点，每个节点包含：

- 当前状态：待开始、感应中、铜钱落定、已锁定、待同步、失败可重试。
- 可读结果：几正几反 + 少阴/少阳/老阴/老阳 + 是否动爻。
- 恢复能力：退出再进时定位到最后一个已锁定节点，不重新随机。

### 5.3 等待解读：真实阶段而非假百分比

DeepSeek 等待过程使用离散状态，不编造线性进度：

1. `盘面已锁定` — 立即完成，可先查看。
2. `规则一致性校验` — 完成或明确失败。
3. `生成白话解读` — 运行中，可切到后台。
4. `风险与措辞复核` — 完成后通知。

超过 8 秒显示“可先看盘面”；超过 20 秒允许后台继续并发送本地通知。失败时保留盘面和重试入口。

### 5.4 结果页：先行动，再证据

首屏固定为三个可扫读模块：

1. **一句话看懂**：描述局面，不给宿命式判词。
2. **现在可以做**：最多 3 条有时间范围、可执行的动作。
3. **需要留意**：最多 2 条风险和一个可观察信号。

随后才是“为什么”：焦点爻/值使宫、日月关系、五卦关系、九宫、原典、规则来源和审计信息。所有 AI 句子应能展开查看其引用的确定性字段；找不到依据的句子标为“模型补充视角”，不得伪装成排盘事实。

### 5.5 奇门盘：九宫不是静态表格

- 首屏只聚焦与当前问题相关的 1–3 宫，其余宫降低视觉权重。
- 点击宫位后显示“白话角色 → 门星神干 → 生克组合 → 来源/约定”。
- 固定入口显示“当前只支持拆补转盘时家”；未支持流派可以解释差异，但不能生成伪结果。
- 专业模式允许开启完整九宫、五行色、空亡/马星/四害等图层，并保存显示偏好。

### 5.6 历史与复盘：把可信度建立在现实反馈上

每条记录增加时间线：`起卦 → 当时建议 → 用户采取的行动 → 现实事件 → 回看结论`。支持标签、分组、图片附件、搜索和对比，但分享默认隐藏问题、位置、出生信息和完整 `run_id`。

## 6. iOS / Android 原生体验架构

### 6.1 推荐方案

若目标确实是“极致体验”，推荐 **SwiftUI + Core Motion/Core Haptics** 与 **Jetpack Compose + Sensor Framework/平台触觉** 两套原生客户端，共享 API、状态机、文案、设计令牌、规则契约和测试向量，不强行共享 UI 代码。

Flutter + Impeller 可作为预算受限时的第二选择：一套 UI 代码可以更快覆盖双端，且 Impeller 已在 iOS 和 Android API 29+ 默认使用；但体感、触觉、后台任务、通知和设备兼容仍需原生桥接与真机分级。当前 Web/Streamlit 前端没有足够高价值的 UI 代码值得为了复用而选择 React Native。

### 6.2 原生信息架构

- **首页**：问一件事、查看今日记录、继续未完成任务；不默认展示全部术数入口。
- **起卦**：问题 → 方法与规则确认 → 体感/点按/手工 → 六爻锁定。
- **结果**：白话 → 证据 → 原典 → 追问 → 现实反馈。
- **奇门**：问事奇门、终身奇门分开入口；先选任务，再进盘。
- **案例**：历史、标签、对比、附件、现实反馈和导出。
- **学习**：64 卦、术语、方法差异、公开基准盘；与个人结果通过上下文链接相连。
- **设置**：流派/时间约定、显示深度、动效/声音/触觉、隐私与数据导出。

### 6.3 摇卦状态机与感官反馈

`准备 → 校准 → 已就绪 → 感应动作 → 结果已锁定 → 铜钱动画 → 一爻完成 → 下一爻 → 六爻完成`

关键原则：先用安全随机和服务端契约锁定结果，再让动画表现该结果；传感器只决定触发时机和视觉能量。

| 事件 | 视觉 | 触觉 | 声音 |
| --- | --- | --- | --- |
| 动作进入有效区间 | 能量环收束 | 极轻反馈 | 无 |
| 三枚铜钱碰撞 | 每枚独立落定 | 三个克制触点 | 三层金属碰撞 |
| 一爻锁定 | 爻线从中心生成 | 双短脉冲 | 低音确认 |
| 动爻出现 | 一次翻转后停止 | 短—停—重 | 轻微泛音 |
| 六爻完成 | 镜头拉远组装卦象 | 成功序列 | 完成音，可关闭 |

遵循系统设置和“少即是多”：高频动作使用平台预定义触觉；Android 高级触觉必须有硬件能力降级；不支持清晰反馈时宁可不震动。

### 6.4 动画与性能门槛

- 输入到首个视觉反馈 P95 ≤ 80ms；有效摇动到触觉 P95 ≤ 60ms。
- 中高端真机稳定 60fps；支持 120Hz 的设备可跟随系统刷新率，但不作为功能依赖。
- 动画优先修改绘制层属性，避免在每帧触发布局和大范围重组。
- 铜钱、粒子和音频资源预热；切后台立即暂停传感器、物理和渲染。
- 提供减少动态、2D、静音、无触觉和快速完成模式；所有状态仍必须有文字。
- 用真实设备记录掉帧、功耗、热量和触觉一致性，模拟器不作为最终验收。

## 7. 三种可选视觉方向

在开始原生 UI 实现前，先用相同的“问题输入—一爻落定—结果首屏—奇门九宫”四个页面生成三组视觉稿，只选择一组进入代码。

1. **天文铜仪（推荐）**：宋代浑仪、青铜、墨色、星盘刻度；科技感来自精密仪器和数据层，不依赖霓虹。最能承接“可核验、严谨、传统文化”。
2. **墨玉光栅**：黑玉、宣纸纤维、微弱冷蓝光栅；更安静现代，适合高频日用和长文本阅读。
3. **数字简牍**：竹简/木牍的模块秩序结合现代卡片与清晰动效；学习属性强，对新人最友好，但仪式感较弱。

三组都禁止满屏太极、随机符文、夸张霓虹和持续旋转；专业可信度来自信息结构与证据，不来自“神秘特效”。

## 8. 竞品录像采集方法

公开搜索可以得到功能、评分、截图、版本记录和部分演示视频，但无法可靠判断触觉强弱、动画过渡、权限拒绝、弱网等待、付费墙时机和长时间使用负担。因此建议用户补充 3–5 个真机录像，与公开研究合并评审。

优先顺序：

1. 论藏甲-奇门或大师奇门：看专业设置、九宫信息密度和宫位交互。
2. 天时六爻或六爻排盘：看起卦、排盘、记录、批注和复盘效率。
3. 爻知 YaoWise：看现代 AI 叙事、等待、追问和历史。
4. 易掌经：看大型综合产品的首页分流、付费墙和新人路径。
5. 南易六爻：看硬币教学、正反面判定和轻量起卦。

每个 App 录 2–5 分钟即可，必须包含：首次打开/授权、完成一次起卦或排盘、等待过程、结果展开、历史保存、设置和付费墙。开启系统“显示触摸位置”（Android）或口述点击意图；不要录入真实出生信息、账号、手机号或私人问题。只从 App Store、Google Play 或手机厂商官方商店安装，不使用来路不明 APK。

### 8.1 2026-08-01 三段真机录像审查

录像未全部显示 App 名称，因此以下使用 A/B/C 标识；B 的功能结构与易掌经公开产品页高度吻合，C 的界面与爻知 YaoWise 一致。名称不影响交互结论。

#### 录像 A：极简筮卦工具（20.5 秒）

- 约 0.5 秒开始，9.5 秒显示完整卦名与结果入口，14 秒进入本卦/变卦和原典页。
- 每次触发后，新爻从灰色占位过渡为黑色；动爻使用红色，并带有左右滑入/合拢的微动效。
- 优点是极快、安静、几乎没有学习成本；米灰底色和大留白让仪式不显廉价。
- 问题是没有六次进度、正反面、老少阴阳、当前爻位和锁定状态；底部导航一直可见，仪式沉浸感有限。
- 结果以原典长文为主，适合已经懂术语的人，不回答“这对我现在意味着什么”。

可借鉴：克制留白、爻线进入动画、十秒快速模式。不可照搬：信息缺失和原典即结论。

#### 录像 B：综合术数 App 的六爻流程（97.6 秒）

- 首页把八字、紫微、合盘、六爻、奇门和大量工具平铺，入口多但认知负担高。
- 表单包含性别、出生时间、求测方向、问题和起卦方式；“求测方向”使用长列表，能帮助模型理解场景，但打断输入节奏。
- 约 38–44 秒使用水墨、呼吸文案和“我已静心”建立仪式；46 秒进入摇动页。
- 约 48–68 秒完成六次摇动。龟壳、三枚铜钱、爻线和 `1/6、3/6、5/6` 等文字形成了三重反馈；铜钱每轮出现、翻转、落定后再进入下一轮。
- 页面有独立音乐开关，录像本身也包含非静音音轨；但录屏无法证明是否存在触觉反馈。
- 结果页约 70 秒出现，盘面信息很完整；后半段以“现状与焦点、潜在变动情况、具体问题分析、未来趋势、行动方向、风险问题”等按钮继续分层，并以“解锁完整分析”承接付费。

可借鉴：每爻的物理对象反馈、完整六次计数、完成场面、专业信息分层。需要改进：用铜钱而不是龟壳承担主角、缩短前置表单、减少首页功能堆叠、不要让付费按钮盖过首个有用结论。

#### 录像 C：爻知 YaoWise（243.97 秒）

- 视觉使用薄荷绿、暖黄、浅灰和大留白，整体最接近现代原生 App；输入问题、侧边菜单、历史和会员中心均较完整。
- 会员年费页在主流程早期即可到达，录像显示 ¥449；过早暴露高价会员会放大用户对后续结果是否“为了付费而设计”的怀疑。
- 约 75–90 秒以“静下心来”和六次轻触完成卦象，动画平滑，但缺少正反面和老少阴阳的即时教学。
- 起卦完成后又插入 3 个背景问题和确认页，约 20 秒后才进入盘面。它提高了 AI 上下文质量，却破坏“起卦已完成 → 立即看到确定性结果”的心理连续性。
- 基础结果把问题摘要、八字辅助、解读风格、盘面和“开始分析”分成卡片，信息结构明显优于传统长文。
- 深度分析等待是三段式：`体察心境 → 寻找答案 → 落笔成文`，显示已用时间、预计时间、当前阶段秒数，并允许自由浏览和完成后通知。这是三段录像里最成熟的长任务状态设计。
- 多种解读人格和继续解读使用余额/付费解锁；在证据层不够清晰时，容易让用户把不同文风误认为不同规则结论。

可借鉴：长任务分阶段、后台浏览、完成提醒、结构化摘要和连续追问。需要改进：确定性盘应先出现；补充背景在起卦前一次完成或设为可跳过；“解读人格”只能改变表达，不能改变盘面事实；会员不应阻断第一次完整结论。

### 8.2 三段录像合成后的产品决策

| 体验目标 | 采用来源 | 本项目的实现方式 |
| --- | --- | --- |
| 快速与克制 | A | 增加“10 秒快速模式”，但仍显示六节点和爻态文字 |
| 物理仪式与每爻反馈 | B | 手机摇动 + 三枚真实质感铜钱 + 视觉/声音/触觉同步 |
| 长任务透明度 | C | 盘面锁定、规则校验、白话生成、风险复核；允许后台和通知 |
| 专业可信度 | 本项目现有优势 | 起盘方法、时间约定、规则版本、确定性依据和已知限制持续可见 |
| 新人可读性 | C 的结构化卡片 + 本项目白话层 | 一句话、行动、风险在前，术语和原典按需展开 |
| 专业效率 | B 的盘面 + 天时六爻/论藏甲公开能力 | 专业模式、图层设置、卦例批注、对比和现实反馈 |

最终不选择“极简到缺少状态”、也不选择“仪式很长却先锁付费”、更不选择“AI 文风替代规则解释”。原生 App 的核心叙事应是：**先让用户清楚完成一次动作，再立即交付可核验盘面，最后用透明的异步过程生成可读建议。**

## 9. 发布前专业门槛

1. 六爻和奇门分别由至少 2 名互不隶属的长期使用者进行盲测式盘面对照。
2. 奇门基准集达到至少 30 盘，覆盖节气交界、阴阳遁、上中下元、旬首、中宫寄宫和晚子时。
3. 六爻基准集覆盖 64 卦、静卦、单动、多动、六爻皆动、飞伏神、空破冲合和历法边界。
4. 每个对外专业结论可定位到规则字段；模型补充与确定性事实视觉区分。
5. “支持的流派、约定、版本、来源、已知限制”在起盘前和结果页均可查看。
6. 完成 iOS/Android 高中低设备的运动、触觉、帧率、断网恢复、后台恢复和无障碍验收。
7. 商店文案禁止“最准、改命、保证结果”等无法验证或具有误导性的承诺。
